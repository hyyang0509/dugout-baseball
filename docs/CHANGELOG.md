# DUGOUT｜棒球經理 — v0.3 半季與事件 MVP

## 執行與部署

此版本為無外部前端依賴的 HTML/CSS/ES modules 靜態應用，託管目錄 `dist/`。

- 遊戲介面：`dist/app.js`、`dist/styles.css`、`dist/index.html`
- 獨立模擬引擎：`dist/engine.js`
- 球員資料：`dist/data/roster_mlb.json`
- 資料抓取腳本與 Python 安裝需求：`data_pipeline/`
- 測試：`node --test tests/engine.test.js`
- Site 身分與發布設定：`.openai/hosting.json`

## 本版體驗

使用者選擇真實 MLB 球隊，調整九人打線與指定先發投手，按一下推進一天或七天。每次處理全聯盟比賽，同步更新戰績、打擊與投球累積數據。投手自動換投並隨時間恢復體力；冷熱手感與事件影響球員狀態。打者可依近三季守備出賽紀錄選擇多守位，九人必須涵蓋完整守備。

81 場生成賽程，先與其餘 29 隊各主客場交手一次，再加 23 場；每隊 40 或 41 場主場。聯盟前四名晉級，四強三戰兩勝，冠軍五戰三勝。延長賽自第十局安排二壘跑者。

瀏覽器 localStorage 自動儲存，key 為 `dugout.save.v1`。儲存涵蓋亂數種子、打線、輪值、戰績、個人成績、疲勞、事件、季後賽與最近完整戰報；不重複寫入靜態球員資料。完整季末存檔測試約 615 KB。每次模擬失敗會回復當日開始前狀態。清除瀏覽器網站資料將刪除進度，跨裝置同步尚未實作。

## 相較完整 PRD 的明確簡化

- 只開放 MLB；CPBL 尚無通過真實回應驗證的資料，因此不放假名單。
- 採 81 場半季與統一聯盟戰績，場次為 MLB 162 場的一半，但賽程仍是生成的，未採真實 MLB 賽程、分區與外卡制度。
- 本機存檔使用 localStorage，未啟用 IndexedDB、雲端或六碼存檔。
- 前端採原生 JavaScript modules，未引入 React、Vite、Tailwind 或 TypeScript 建置依賴。
- 比賽採簡化打席機率模型，沒有完整 Log5／WPA。焦點依逆轉、後段超前及全壘打等重要性排序。
- 球員跑壘、雙殺、失誤、犧飛為簡化模擬，無盜壘、代打、守位適性懲罰及手動局中調度。
- 投手顯示 RA9（所有失分／九局），不冒充 ERA。投打統計包含季後賽，團隊勝敗只計例行賽。
- 名單來自 40 人名單快照；遊戲為假想球季，開季全員健康，未匯入真實 IL 限制或球員合約。
- 事件為訓練、團隊恢復與短期傷病，避免替真實球員捏造犯罪／場外醜聞。
- 已加入一對一交易（可附現金）及遊戲財務；尚未加入多人包裹、自由球員、真實合約、選秀、養成與跨年度休賽期。季末可重新選隊開季。
- 手感效果為 ±9%，持續 3–5 日；投手體力每模擬日恢復 18 點，疲勞時降低能力。

## 驗證

24 項自動測試：完整主客場賽程、全部球隊打線／輪值、固定種子可重現及分數一致性、傷兵遞補與事件暫停、完整球季到冠軍與存檔序列化、二刀流 DH／投手能力。

瀏覽器實測：選隊、單日模擬、七日模擬、完整戰報、打線自動安排與順序調整、重新載入後保留進度、戰績榜。390px 寬 iframe 內檢查手機版面，整頁無水平溢出（表格本身可左右滑動）。未以實體 iPhone 測試。

## v0.2 更新

- 桌機字體加大，縮小首頁裝飾區，以球隊名稱及戰績取代宣傳標語。
- `positions` 由原始近三季 fielding 紀錄及主守位補齊，打者皆可 DH；`assignFielding` 以配對演算法保證九個守位不重複。`setPosition` 在兩人都適任時互換。
- 打線、打者表格及個人頁皆顯示體力。普通打者每場消耗 10 點，連續出賽隔日恢復 5 點，前一日休息則恢復 16 點；二刀流依投手規則額外處理。低於 35% 安排健康替補，低於 35% 有能力懲罰。
- `teamOf`／`rosterFor` 讀取存檔中的 ownership，而不修改原始球員資料。歷史完整戰報保留出賽當時所屬隊伍，交易不會改寫既有戰報。
- 交易為本隊球員換一名外隊球員，可附加 0–2,000 萬美元遊戲現金。交易前檢查雙方薪資預算、本隊剩餘薪資準備金、健康及守備陣容；對方依能力、年齡、薪資估值。第 44 日起及季後賽關閉。
- 薪資、球團預算、門票、營運收入及費用全部為遊戲設定。薪資依能力估計，是 58 場短賽季的合約總額，不宣稱真實 MLB 年薪。以 58 日分攤支付，季後賽不再扣本季合約薪資。
- 球團現金、薪資預算、每日薪資、剩餘應付薪資、營運收入／費用及交易現金淨流量可查看；主場票價 15–80 美元影響觀眾人數、門票與球場消費。
- 儲存鍵仍為 `dugout.save.v1`，內容升級 `version:2`。`migrateSeason` 保留進度、成績與打線；舊存檔啟用財務當日起記帳，沒有回溯扣薪。
- 14 項測試涵蓋完整球季、守位合法性、疲勞遞補、v1 升級、交易原子拒絕、交易後所有權及輪值／薪資、每日帳務一致性、票價效果。瀏覽器另實測附現金成交、多守位互換、交易後繼續比賽，以及手機布局與重新載入。

## v0.3 更新

- `simulateGame` 每場開賽前呼叫雙方 `optimizeLineup`，依守位、手感與體力重新選九人並排棒次；不是只排一次或只替補傷兵。單日、連續七日與季後賽走相同入口，AI 球隊也適用。手動打線頁是當下預覽，開賽時會再最佳化。
- 新賽季 81 場：保留原本 58 輪，附加 23 輪。以加虛擬節點的 Euler circuit 定向額外比賽，保證每隊 40/41 場主場；每對球隊交手 2/3 次。
- v1/v2 正在例行賽的 58 場存檔自動延長到 81 場，已打過的賽程與統計不變。已進入季後賽／已結束的舊存檔保留 58 場制度及原本冠軍，不清除系列賽。
- 舊存檔未付薪資依原本剩餘比例保留，再分攤到延長後的剩餘日數，不重算已付薪資、不增加合約總額；新存檔平均分攤 81 日。交易截止依賽季長度計算，新 81 場球季在第 61 日起關閉。
- 事件率由 14% 提高到每模擬日 40%，遇到事件仍暫停。條件分布：傷病 10%、訓練 17%、更衣室 33%、本隊交易提案 23%、AI 聯盟交易 10%、團隊恢復 7%。不符合交易窗口／陣容條件時改為更衣室事件。每日傷病期望率約 4%，接近原本 4.2%，沒有隨總事件率加倍。
- 更衣室氣氛 0–100，預設 50，影響實際能力最多 ±5%；每日往 50 回歸一點。事件選項在氣氛與體力間取捨。
- 本隊交易提案保留明確球員與現金條件，玩家選擇接受或拒絕。接受時重新驗證預算／所有權／傷兵條件，過期提案安全拒絕；本隊不會被自動交易。
- AI 聯盟交易僅限其他球隊，使用相同陣容與預算檢查並更新實際名單，再以事件提供消息。本隊交易頁只顯示本隊紀錄。所有事件與交易都屬於模擬，不是真實 MLB 消息。
- 頁面右上方與「球團辦公室 → 存檔與設定」可切換亮色／暗色。以 `dugout.theme` 儲存於本瀏覽器，HTML 載入前套用已選配色，避免閃白。
- 存檔內容版本升為 3，原有鍵 `dugout.save.v1` 不變。24 項測試包含逐場／連續模擬排線、81 場主客場分配、舊賽程與薪資遷移、已進季後賽保護、更衣室效果、交易接受／拒絕／失效及 AI 交易隔離。


## v0.4：事件與聯盟日報
- 16 種具體劇情：8 種更衣室互動、6 種離奇傷病、2 種虛構人物場外紀律事件。一般劇情依當前所屬球隊選入真實球員姓名；酒駕、家暴僅使用明確標示的架空培訓球員，沒有真實球員 ID。
- 本隊事件維持每日 40% 機率並暫停等待決策；另有每日 55% 機率產生其他球隊消息，不阻斷模擬。傷病會實際影響可用名單，並保護最後的合法守備陣容。
- 新增聯盟新聞獨立頁與首頁摘要。完整保留每日 15 場賽果、單日焦點、重大勝負、交易、劇情與決策結果及季後賽里程碑，支援日期與分類篩選。所有消息明示遊戲模擬，沒有抓取真實新聞。
- 存檔升級為 v4，保留既有進度。舊紀錄只回填目前存檔仍有的賽果與決策，不捏造未留存的歷史；新新聞獨立於短期賽果緩存保留至本季結束。
- 驗證：29 項 Node 測試，涵蓋所有劇情、虛構人物隔離、傷病名單可用性、新聞儲存與舊版升級。


## v0.5：情境決策與交易比較
- 八種更衣室事件各有三個專屬行動（共 24 選項），直接列出氣氛、全隊/指定球員體力、冷熱狀態持續日數與活動支出。效果實際套用，聚餐及空間改善費用入營運帳，必須保留剩餘薪資；AI 球隊也套用相同規則。
- 事件狀態從下一個比賽日起持續所示日數，避免一日效果在首場前消失。待處理的舊版具體情境會升級選項，未具備情境 ID 的更舊事件保留原決策相容。
- 球隊圓形標記使用單一大寫字母（LAD → L、BOS → B），保留完整隊名與賽果縮寫以辨識同字母球隊。
- 主動交易頁、確認視窗、隨機交易提案與聯盟成交消息均有並列比較表：守位、年齡、能力評級、體力/狀態、遊戲薪資及本季投打成績。成交消息沿用交易前的雙方球隊方向。
- 先發打線下拉選項列出完整可用守位，例如 Mookie Betts · 2B/SS/RF/DH。
- 驗證：34 項測試通過；桌面交易表、隨機提案表、打線選單及 390px 手機情境決策介面均經瀏覽器檢查。


## v0.6：重新開局與年度經營
- 完季首頁新增手機可見的「前進下一季／重新開始遊戲／歷年紀錄」入口，手機頂部按鈕同步改為下一季。可用原隊初始名單重玩 2026，或重新選隊；新遊戲成功儲存後才取代存檔。
- 新增 2026 → 2027 → 2028… 年度延續，沿用交易後球員所屬、票價、球團現金。每年重新累積戰績、球員單季成績、新聞、交易紀錄與經費帳；體力、傷病與手感在休賽季恢復。
- 球員年齡每年增加，能力依年齡與潛力做種子隨機成長/退化；老將以隨年齡增加的機率模擬退役，45 歲必退。退役時按原守位產生 18–22 歲虛構新人，保留守位覆蓋；不足 42 人的球隊每年額外補 1 打者、1 投手。既有超過 42 人的名單保留，不額外膨脹。所有未來變化明示為遊戲模擬。
- 進入下一季前可查看本隊全部能力變化、退役、新人與新季薪資。年度薪資按新能力重估，薪資預算重設；董事會僅補足「新季薪資 + 2,000 萬美元」資金底線，舊現金保留，補助列入收入與帳本。
- 球團辦公室新增歷年紀錄與最新休賽季名單變化。逐季保存本隊戰績、排名、聯盟戰績、冠軍、HR 前五名與季末現金摘要；完整逐日新聞依本季儲存。
- 存檔格式 v5，自動相容 v1–v4 完季存檔。跨季球員池隨存檔保存，讀取時先恢復動態名單，避免退役或新人造成名單驗證失敗；重新開局使用獨立的原始資料。
- 驗證：41 項測試；連續三個完整球季可完成、跨季推進到 2046 後名單與存檔仍可用。手機瀏覽器實測舊存檔 → 下一季 → 再開啟出賽、原隊重玩及改選紅襪後重新載入。
