## 2. GM 名字與生涯檔

### 2.1 開新遊戲
- 選隊畫面多一欄「GM 名字」（1–12 字，去頭尾空白；不可空白）。
- 已有 GM 生涯檔時，可以從下拉選單「延續既有 GM」，或「建立新 GM」。
- 同名的新 GM 會加上編號（例：「阿明 (2)」），不會合併。

### 2.2 儲存位置（遊戲存檔之外）
- 存在 IndexedDB 同一個資料庫，鍵為 `dugout.gm.v1`，沿用 v3.3 的 storage.js（gzip、退回 localStorage、合併寫入、解不開時報錯）。
- 「重新開始遊戲」只取代世界存檔（`dugout.world.v1`），不碰 `dugout.gm.v1`。
- 世界存檔記下 `w.gmId`，指向生涯檔裡的 GM。
- 「匯出存檔」的 JSON 會附上這位 GM 的生涯資料；「匯入存檔」時若本機沒有這位 GM，就加入；已有則依 3.4 的規則合併，不會重複計算。
- 「存檔與設定」另外提供「匯出 GM 生涯檔」「匯入 GM 生涯檔」。

### 2.3 格式
```
{ version: 1,
  gms: [{ id, name, createdAt,
          reputation,            // 0–100
          seasons: [...],        // 見 3.1
          stints: [...],         // 帶隊時間軸，見 3.2
          achievements: [{id, year, worldId}],
          earnings: {salary, bonus, penalties},
          worlds: [worldId...] }],
  lastGmId }
```

### 2.4 舊存檔
- 讀到沒有 `gmId` 的世界存檔時，跳出一次視窗請你替 GM 命名（可略過，預設「無名 GM」）。
- 這個存檔裡 `s.gm.history` 已有的球季會匯入生涯檔，標示「v3.5 前的紀錄」；舊紀錄沒有季後賽資料，季後賽次數只從能判斷的欄位（冠軍）補。

## 3. 統計

### 3.1 每季一筆（`seasons`）
`{worldId, year, league, teamId, team, w, l, playoffs, champion, grade, confidenceEnd, fired, midseason, difficulty(本季最低), reputationBefore, reputationAfter, salary, bonus}`
- 勝敗只算例行賽（與球隊戰績一致），季中轉隊的球季兩隊各一筆。
- **去重**：以 `worldId + year + teamId` 為鍵。讀回舊存檔重玩同一季，會覆蓋那一筆，不會多算勝場、冠軍或收入。

### 3.2 帶隊時間軸（`stints`）
`{worldId, league, teamId, team, from:{year, day}, to:{year, day}|null, reason}`，reason：上任／解職／約滿離開／跳槽／重新開始。

### 3.3 名人堂顯示
- 總勝敗、勝率、季後賽次數、冠軍數、執掌球季數、被開除次數。
- 帶過的球隊時間軸（聯盟顏色區分）。
- 個人收入：年薪＋績效獎金−違約金，**遊戲薪資**，標示「遊戲設定，非真實薪資」。
- 目前頭銜（沿用 v1.8 的 GM 評價）與成就。
- 每季最低難度。

### 3.4 個人收入
- 年薪：依聯盟與球團預算。基準 = 球團年度預算 × 0.4%，限制在 美職 US$1.0M–4.0M、日職 0.4M–1.5M、韓職 0.25M–0.8M、中職 0.12M–0.4M（遊戲美元）。合約期間鎖定。
- 績效獎金（季末發）：打進季後賽 10%、晉級每輪 +5%、冠軍 +25%、考核 80 分以上 +10%（皆為年薪百分比）。
- GM 收入只記在生涯檔，不從球團現金扣（球團財務對帳不變）。

## 4. 聲望（0–100）

- 新 GM 起始 **20**。季末計算一次；季中解職另扣一次。
- 季末變化：
  - 戰績：(例行賽勝率 − .500) × 40
  - 季後賽：打進 +3，每晉級一輪 +2，冠軍 +10
  - 董事會考核：(考核分數 − 60) × 0.1
  - 頭銜：冠軍操盤手、金頭腦 +2；暴君、豪賭客 −2（其他 0）
  - 聯盟權重（只乘正值）：美職 ×1.15、日職 ×1.0、韓職 ×0.9、中職 ×0.85
  - **難度加成（只乘正值）**：輕鬆 ×0.8、標準 ×1.0、困難 ×1.25、地獄 ×1.5
  - 回歸：每季 −(聲望 − 30) × 4%（避免一路漲到 100 就停住）
- 被解職：−8；跳槽（提前解約）：−4。
- 顯示等級：0–29 無名、30–54 普通、55–74 知名、75–89 頂尖、90+ 傳奇。

## 5. 成就（第一批，約 12 個）
首勝、首次季後賽、首冠、連霸、三連霸、百勝 GM（生涯例行賽 100 勝）、十年老店（同一隊 10 季）、救火隊（季中接任後打進季後賽）、浪子回頭（被開除後 3 季內奪冠）、跨海挑戰（跨聯盟轉任）、雙聯盟冠軍、四聯盟制霸、地獄生還（地獄難度完成整季沒被開除）、地獄冠軍。

## 6. 挖角邀約（v3.6）

- 時機：休賽季開始時產生（「進入休賽季」那一步），在休賽季頁上方列出，最多 3 個。以世界種子＋年份產生，重新整理不會變。
- 依聲望：
  | 聲望 | 邀約來源 |
  | --- | --- |
  | 0–54 | 同聯盟弱隊（戰力後三分之一），最多 1–2 隊；約滿或被開除時一定至少 1 隊 |
  | 55–74 | 同聯盟任何球隊，含強隊（前三分之一） |
  | 75+ | 加上跨聯盟：中職、韓職 → 日職或美職的弱隊；日職 → 美職的弱隊 |
  | 90+ | 跨聯盟可以是強隊 |
- 原東家：合約到期時，若信任度 ≥ 解職門檻＋10，原東家提出續約。
- 往較弱聯盟的邀約（例：美職 → 中職）：初版不產生（見問題 2）。

## 7. GM 合約（v3.6）
- 開新遊戲、接任新球隊時簽約，年限 2–4 年（新遊戲固定 3 年；邀約上寫明年限與年薪）。
- 約滿：休賽季可自由選擇邀約或續約，不必付錢。
- 提前跳槽：付違約金 = 剩餘合約年薪 × 50%（從 GM 個人收入扣），聲望 −4，原東家球迷不滿（新聞＋鄉民發文；之後對戰原東家時有專屬留言），GM 評價加上「跳槽」紀錄。
- 被解職：合約自動終止，不付違約金，也不領剩餘年薪。

## 8. 跨聯盟轉任（v3.6，技術重點）
- 接受跨聯盟邀約後，原聯盟剩下的休賽季交給電腦處理；完成休賽季時：
  - `w.userLeague` 改成新聯盟，`w.teamId` 改成新球隊。
  - 舊聯盟的 season 加上 `aiOnly`、跑一次 trimAI（舊的年度變化報告會清掉）。
  - 新聯盟的 season 移除 `aiOnly`，建立 GM 層（董事會、總教練、輿情），董事會以該難度的起始信任度 −5 開始。
  - s.gm（評價、本季計數）跟著 GM 移到新聯盟；舊聯盟留下的 s.gm 清掉。
  - 偵查：新聯盟的球員改為已知能力（與目前「自己聯盟看得到真實能力」一致）。
- 新增「跨聯盟轉任」的存檔測試：轉任後 restoreWorld、模擬一季、再換季都要成功，球隊九個守位完整，財務對帳。

## 9. GM 名人堂頁
- 側邊欄新增「GM 名人堂」；選隊畫面也有入口（不需要進行中的存檔）。
- 列表：所有 GM 依聲望排序，顯示名字、聲望等級、冠軍、勝率、球季數。
- 點進去：統計、時間軸、每季表、收入、成就、最低難度。
- 文字標示：「GM 生涯為遊戲紀錄；薪資為遊戲設定」。

## 10. 測試
- 生涯檔：與世界存檔分開；重新開始不清除；同一季重玩不重複計算；匯出入合併。
- 聲望：方向（勝率、冠軍、難度加成只影響正值）、上下限 0–100。
- 邀約：各聲望區間的邀約來源、種子穩定。
- 合約與違約金、被解職不付違約金。
- 跨聯盟轉任後的完整一季與換季。
